# Rajshree Energy — Task Delegation Platform

Internal task delegation and tracking for Rajshree Energy (~20 staff).

## Stack

- **Frontend:** Next.js 14 (TypeScript) + Tailwind CSS — `apps/web`
- **Backend:** Express (TypeScript) — `apps/api`
- **Database / Auth:** Supabase (PostgreSQL + Auth)
- **Shared types/schemas:** `packages/shared`
- **Hosting:** Vercel (web + serverless API) with Vercel Cron for recurring occurrence generation

## Features

- Admin and staff can create/delegate tasks
- Optional per-task approval by the **delegator**
- One-time and recurring tasks (daily/weekly/monthly/yearly)
- Computed statuses: Pending, Overdue, Sent for Approval, Completed
- Staff management with `firstname.lastname` usernames
- Dashboard summaries, filters, notifications, activity log
- Backend authorization + Supabase RLS

## Environment variables

Copy `.env.example` to `.env` at the repo root and also into `apps/web/.env.local` as needed.

| Variable | Used by | Description |
|----------|---------|-------------|
| `SUPABASE_URL` | API | Supabase project URL |
| `SUPABASE_ANON_KEY` | API | Supabase anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | API | Service role key (**server only**, never expose to browser) |
| `NEXT_PUBLIC_SUPABASE_URL` | Web (optional) | Same as Supabase URL if client auth is added later |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Web (optional) | Anon key |
| `NEXT_PUBLIC_API_URL` | Web | API base URL (`http://localhost:4000` locally) |
| `API_PORT` | API | Default `4000` |
| `CORS_ORIGIN` | API | Frontend origin(s), comma-separated |
| `APP_TIMEZONE` | API | Default `Asia/Kolkata` for recurrence times |
| `CRON_SECRET` | API | Bearer token for `/cron/generate-occurrences` |

## Database setup

1. Create a Supabase project.
2. In the SQL Editor, run [`supabase/migrations/001_initial_schema.sql`](supabase/migrations/001_initial_schema.sql).
3. Create the first admin Auth user in **Authentication → Users → Add user** (email + password).
4. Insert the admin profile using [`supabase/seed_admin.sql`](supabase/seed_admin.sql) (replace UUID/email/name).
5. Confirm the admin can log in with email (or username after profile insert).

## Staff provisioning

1. Sign in as admin.
2. Open **Staff** → enter first name, last name, email.
3. System generates username (`firstname.lastname`, or `firstname.lastname2` on conflict).
4. Copy the temporary password shown once and share securely.
5. Staff sign in and are forced to change password (`must_change_password`).

## Recurring task scheduler

Occurrences are generated by an idempotent endpoint:

```http
GET|POST /cron/generate-occurrences
Authorization: Bearer <CRON_SECRET>
```

Uniqueness on `(recurring_schedule_id, occurrence_date)` prevents duplicates if the job runs twice.

### Vercel Cron

`apps/api/vercel.json` schedules the job hourly. Configure `CRON_SECRET` in the API project env. For Vercel Cron auth, also send the secret as `Authorization: Bearer …` (configure via a secure wrapper or use the same header in a scheduled external ping).

### Manual / local

```bash
curl -X POST http://localhost:4000/cron/generate-occurrences \
  -H "Authorization: Bearer $CRON_SECRET"
```

## Deployment

### Frontend (Vercel)

1. Import the repo; set root to `apps/web` (or use a monorepo config).
2. Set `NEXT_PUBLIC_API_URL` to the deployed API URL.
3. Build command: from repo root `npm install && npm run build:shared && npm run build -w @rajshree/web` (adjust for your Vercel project settings).

### API (Vercel serverless)

1. Deploy `apps/api` as a separate Vercel project (entrypoint `src/vercel.ts`).
2. Set all API env vars including `SUPABASE_SERVICE_ROLE_KEY` and `CRON_SECRET`.
3. Set `CORS_ORIGIN` to the frontend URL.

Alternatively host the Express API on Railway/Render/Fly for a long-lived Node process; cron can still call the same HTTP endpoint.

## Approval behaviour

- On create: toggle **Approval required**.
- If off → receiver “Mark completed” → **Completed**.
- If on → receiver submit → **Sent for Approval** → only the **delegator** can approve/reject.
- While awaiting approval, the task does **not** become Overdue.
- Reject returns the task to active (Pending/Overdue based on deadline).

## Security notes

- Never put `SUPABASE_SERVICE_ROLE_KEY` in frontend env.
- Task access is enforced in the API; RLS adds defense in depth for direct Supabase access.
- Inactive users cannot authenticate successfully for app use.
- Destructive actions (cancel) require confirmation in the UI.

## Remaining limitations

- Email notifications are not implemented (in-app notifications only).
- Password reset “forgot password” email flow is not built; admins can recreate/reset via Supabase Auth if needed.
- Search by staff name is limited; admin search covers task title/description (filter by staff IDs for people).
- Vercel Cron may require Pro for sub-daily schedules depending on plan; hourly is configured.
